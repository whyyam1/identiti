What this rail does today

Account UUID
Universal foreign key issued at customer creation. acc_<uuid v4>. Every other rail keys off it.
KYC + tier system
Three tiers (0/1/2). IPRS verification stub. Operator-mediated promotions. Hash-chained KYC artefacts.
Step-up authentication
RS256 JWTs, single-use, audience-bound, 60s–10min TTLs by risk tier. Public JWKS for relying parties.
Phone tokenisation
Apps never see raw MSISDNs. HS256 phone tokens resolved via a Todoku-internal scope; AES-256-GCM ciphertext only.
Phone-change flow
Two-OTP verification, cooldown-enforced, step-up gated. PHONE_CHANGED published cross-rail.
Operator console
Suspend/reactivate, tier override, KYC review queue + approve/reject, audit-log read.
Delegated-authority signing
RS256 token issuance for AI agents acting on a user's behalf, jointly designed with the Helpan AI rail.
Tier history
Customer-facing paginated history of every tier assignment, with the partial-unique index enforcing data integrity.

Engineering posture

  • HMAC-SHA-256 service auth + scope-based authorisation on every endpoint
  • Hash-chained audit log (SHA-256 chain, 7-year retention)
  • Row-level security on every database table
  • AES-256-GCM phone encryption; PBKDF2 (100k iterations) phone-hash
  • Single-use JWT enforcement via JTI tracking + partial-unique indexes
  • TypeScript strict mode, Drizzle ORM, AJV (JSON Schema 2020-12)
  • ESLint + Prettier wired; CI runs lint → format → typecheck → test → build
  • Reproducible deploys: Nixpacks, pinned pnpm, `pnpm install --frozen-lockfile`
